Put an application online, without learning Kubernetes.

MyInfra is an open source interface. You pick an application, a name, and a machine or a group of machines. The domain, the certificate, and the proxy follow. The screen does not talk to you about namespaces.

The program you start is the program you can read. The published image contains the same binary. Your installation's secrets are not in it.

Read the README

Features

Catalogue

Ready-made applications, or your own image. The same form either way.

Machine or cluster

A Docker container on a machine. Pods on a k3s cluster. Traefik in front of both.

Pause

The pods stop. The disk and the data stay.

Domain and certificate

The DNS record is written when an account is linked. The name is routed only once the certificate is in place.

Providers

Hetzner, Scaleway, OVH, DigitalOcean, Infomaniak, UpCloud, Akamai, Vultr, Exoscale, Gcore, Kamatera, and IONOS. The token is yours. MyInfra does not resell machines.

Secrets

You declare keys, then check the applications allowed to receive them. Values never come back to the screen.

Copies

Several MyInfra instances of the same owner stay in sync. A replica does not drive the machines.

One file

The interface is inside the executable. Linux, macOS, and Windows.

Architecture

You talk to the interface. The interface talks to the control plane. The control plane keeps state in PostgreSQL and opens the machines over SSH.

Single machine

The agent installs Docker and Traefik, then starts the container. A Docker volume keeps the files when the application needs them.

Cluster

k3s places the pods. Traefik receives the traffic. A database disk stays on one node, for a single pod.

How it works

On the first launch, you choose a password. The master key comes from the environment, not from the database. It seals tokens, private keys, and application secrets.

Creating an application stores the request, then delivers it. On a cluster, the manifest goes out as base64 to kubectl apply. On a machine, the agent receives a script and starts the container. An unreadable value is not applied, and the application already in place is not removed.

Two MyInfra copies exchange database rows. The newer one wins. Sessions stay local. Transfer moves MyInfra to a new machine or to a pod in the cluster, and a page follows the steps.
