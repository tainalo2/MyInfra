Features

Everything a platform team would set up, in one program.

Pick an application, a name and a place to run it. MyInfra handles what you can see, and talks about applications, servers and addresses — not namespaces, ingresses or ports.

A catalogue of applications

Wikis, monitoring, notes, media, sites… or any image. Each app says which registry its image comes from.

Domains and HTTPS

DNS records written for you, Let's Encrypt certificates, addresses you can change while the app runs.

Clusters in minutes

Servers from several providers joined over WireGuard, running k3s and Traefik. An odd number of control planes, set up for you.

Redundancy with one button

Copies spread on several servers, continuous SQLite backups with Litestream, replicated PostgreSQL with CloudNativePG.

Your own images

Private registries with logins, or import a docker save archive — sent or fetched from a URL. MyInfra loads it on the servers itself.

A vault for every secret

Provider tokens, SSH keys and app secrets sealed with AES-GCM. A list never shows a secret in clear text.

Accounts and two-factor sign-in

Several people on one installation, each with a role: administration, deployment or read-only. An account can require a TOTP code. Logins, roles and codes move with a transfer.

See it all on a map

Every server, app and pod, what needs attention, and the hourly and monthly cost at the top of the screen. A machine you add yourself takes the city you choose.

Logs and a terminal

Pod logs, a terminal on the machine or in the pod, CPU, memory and disk meters — on desktop and on your phone.

Templates you can share

Start from one of nine ready-made templates or describe your own, deploy it in one go, and share it as a file — without any secret inside.

Automatic redundancy

One server fails. Your apps keep answering.

MyInfra spreads applications and their data across your servers by itself, and tells you when something still depends on a single machine.

Increase redundancy

Servers

  • Copies of an app run on different servers, never stacked on one
  • A failed node's pods restart elsewhere in about 30 seconds
  • An odd number of control planes, a DNS name pointing at every node
  • Traefik and its certificates move with the cluster, without asking Let's Encrypt again
  • A warning, and one button, for every app still on a single server

Storage

  • Garage object storage on the cluster: three copies of every object on three servers
  • SQLite apps backed up continuously with Litestream, restored on any node
  • PostgreSQL-capable apps moved to a replicated database with CloudNativePG
  • Every move is checked before it counts, and the old disk is never deleted

Transfer

Start locally. Continue online.

Try MyInfra on your laptop in a minute. When you are ready, move it — data, secrets and all — onto a server or into your own cluster, and switch your laptop off.

  1. Run it on your laptop. One executable, its own PostgreSQL, nothing to install.
  2. Build your servers and apps. Everything is driven over SSH: your laptop can sit behind a home router.
  3. Transfer. Pick a new machine at your provider, or a pod in your cluster. MyInfra copies its database and secrets there, gives it its address, then stops the local copy.
  4. Keep going online. MyInfra now runs next to your apps, reachable from anywhere — even managed by itself, inside the cluster it drives.

Terminal

No SSH client, no kubeconfig to copy: open a terminal from MyInfra, on a machine or inside any running copy of an application — from your desk or from your phone.

  • Servers and pods: a root shell on a machine, or a shell in any pod of an application, one click from its page

Templates

Describe a stack once. Deploy it anywhere. Share it with anyone.

A template holds a whole setup — a cluster, its servers and its applications with their addresses. Deploy it in one go, or hand it to someone else as a file.

1Describe

Start from a ready-made template — first steps, website, team workspace, development, monitoring, media… — write one by hand, or create one from a running cluster in a click.

2Share

Export a template as a JSON file and send it, commit it, publish it. It names providers, SSH keys and DNS zones but never carries a token or a secret. Whoever imports it gets it matched to their own accounts and keys.

3Deploy

MyInfra asks only for what is missing — an account, a DNS zone, an existing cluster — shows a summary with the hourly cost, then buys the servers, builds the cluster and puts every app online.

Follow every step, resume after a failure

The cluster, each server and each application report their progress live. A step that fails can be resumed where it stopped; a deployment can be cancelled while it runs.

How it works

From nothing to online in three steps.

MyInfra runs on your laptop or on a server. The machines never need to reach it: every action goes out over SSH.

Start MyInfra

Run the executable. It unpacks its own PostgreSQL, opens your browser and asks for a password. You can add other accounts, each with a role and an optional TOTP code. Then link a provider token, an SSH key and a DNS account.

Add servers

Buy a machine from your provider in a few clicks, or paste one command on a machine you own: it receives the SSH key, and MyInfra finishes the setup. Give that machine a city for the map. Group machines into a k3s cluster joined over WireGuard.

Put apps online

Pick an app from the catalogue or bring your image, give it an address. MyInfra writes the DNS record, gets the certificate, and shows it online only once it answers in HTTPS.

Build it yourself

Every artifact, from the source.

The release executables are produced by the same ./build script you run locally.

Go 1.24+Node.js 24 + npmunzipPostgreSQL 16 (development only)Docker (image only)
Get the code and run in development 
git clone https://github.com/tainalo2/MyInfra.git
cd MyInfra
./dev        # API on :8080, interface on :5173

./dev starts a PostgreSQL in .pgdata, the Go API and the Vite interface with hot reload. On Windows: dev.cmd.

Build one executable 
./build                 # this system, into dist/
./build linux arm64     # one target
./build all             # 6 targets

Builds the interface, embeds it, packs PostgreSQL for the target, then compiles a static binary. VERSION sets what myinfra --version reports.

Build the Docker image 
docker build -t myinfra --build-arg VERSION=dev .
docker compose -f deploy/compose.yaml up -d

The binary on a Debian base with Ansible, Python, the SSH client and OpenTofu, and an external PostgreSQL. The compose file expects POSTGRES_PASSWORD, MYINFRA_MASTER_KEY and MYINFRA_IMAGE.

Test 
go vet ./... && go test ./...
cd web && npx tsc --noEmit -p . && npm run build
E2E_URL=http://127.0.0.1:8080 npm run e2e

Releases: push a v1.2.3 tag or run the Publication workflow; CI builds, checks and publishes everything.

FAQ

Questions

Is MyInfra a hosted service?

No. It is open source software you run yourself. There is no MyInfra account, no subscription and no cloud operated by the project. You use your own provider accounts and your own servers.

How much does it cost?

MyInfra is free under the Apache-2.0 license. You only pay your cloud provider for the servers you choose, and MyInfra shows that cost per hour and per month.

Do my servers need to reach MyInfra?

No. MyInfra drives every server over SSH, so it can run on a laptop behind a home router. Even images you import are streamed to the servers by MyInfra itself.

Which providers are supported?

Hetzner, Scaleway, OVHcloud, DigitalOcean, Infomaniak, UpCloud, Akamai, Vultr, Exoscale, Gcore, Kamatera and IONOS, plus any Linux machine you already have. Scaleway, Hetzner, DigitalOcean, Vultr, OVH and Exoscale have been validated end to end.

Where are my secrets?

In your PostgreSQL database, sealed with AES-GCM. The master key comes from your machine or from the environment, and is never written to the database or the image.

Can I use it in production?

MyInfra is young and was 100% vibe coded. Read the code, try it on servers you can afford to lose, and open issues or pull requests when something breaks.
